# Мониторинг публичных Telegram-каналов

Бот управляет источниками, а отдельная служба `newsbot-telegram` читает их через пользовательский Telegram API (Telethon 1.x). Она не отправляет сообщения от имени аккаунта, не читает личные переписки и не вступает в каналы автоматически. Получателям пишет только @News_crp_bot. Сама сессия технически предоставляет доступ к аккаунту: храните её как пароль; можно использовать отдельный аккаунт.

Telegram API предоставляется бесплатно по его условиям; этот сборщик не вызывает OpenRouter или Checko. Правила и получение реквизитов: https://core.telegram.org/api/obtaining_api_id . Работа с реальным аккаунтом и сетью VPS пока не проверена — для этого необходим ваш вход. Успех доступа к api.telegram.org не гарантирует доступ к серверам MTProto, используемым пользовательским API.

## 1. Реквизиты

Откройте https://my.telegram.org/apps , войдите и создайте приложение через API development tools. Получите собственные `api_id` и `api_hash`. Номер, коды, пароль двухэтапной защиты, api_hash и файл сессии не отправляйте в чат и не помещайте в GitHub.

## 2. Установка на существующем Ubuntu VPS

В SSH от root:

```bash
cd /opt/newsbot
git pull --ff-only origin feature/telegram-admin
.venv/bin/python -m pip install -r requirements-telegram.txt
nano /etc/newsbot.env
```

Добавьте, сохранив старые строки:

```text
TG_API_ID=числовой_api_id
TG_API_HASH=ваш_api_hash
TG_SESSION_PATH=/var/lib/newsbot/telegram-reader.session
```

Общий `NEWS_STATE_PATH` должен оставаться `/var/lib/newsbot/sent.sqlite3`. Владелец `TELEGRAM_ADMIN_ID` и токен бота остаются прежними. Файл настроек — root:root, режим 600. Не запускайте второй экземпляр бота или сборщика.

## 3. Однократный вход через SSH

Если служба сборщика уже запускалась, сначала остановите её: `systemctl stop newsbot-telegram`.

Следующие команды загружают доверенный файл настроек в окружение, не печатая его содержимое. Выполняйте от root в SSH:

```bash
set -a
. /etc/newsbot.env
set +a
runuser -u newsbot --preserve-environment -- /opt/newsbot/.venv/bin/python /opt/newsbot/tgmonitor.py --login
```

Введите телефон, код, полученный от Telegram, и пароль двухэтапной защиты, если запрошен. Ввод скрыт: после вставки нажмите Enter. Сессия сохраняется в `/var/lib/newsbot/telegram-reader.session` под пользователем newsbot с ограниченными правами, без вывода строки сессии. Файл блокировки предотвращает одновременный вход и чтение с одной сессией. Повторный вход потребуется после отзыва сессии в Telegram.

## 4. Постоянная служба

```bash
cp /opt/newsbot/newsbot-telegram.service /etc/systemd/system/newsbot-telegram.service
systemctl daemon-reload
systemctl enable --now newsbot-telegram
systemctl restart newsbot
systemctl status newsbot-telegram --no-pager -l
```

Журнал: `journalctl -u newsbot-telegram -n 30 --no-pager`. При проблемах не публикуйте реквизиты или файл сессии. В журнал намеренно не выводятся сырые исключения с личными данными.

## 5. Управление в Telegram

`/tg` или «Мониторинг Telegram» → «Добавить канал» → `@username` либо `https://t.me/username`. Источник сначала ожидает проверки сборщиком; доступность и тип канала проверяются через API, это не подтверждается одним вводом имени. Поддерживаются публичные вещательные каналы, не пользователи, боты, группы, закрытые приглашения или ссылки t.me/c.

«Каналы» → «Ключевые слова»: слова через запятую, совпадение любого слова/фрагмента без учёта регистра; `все` — без фильтра. До 20 слов по 100 символов. Фильтрация по тексту поста и подписи к медиа, без OCR или распознавания аудио.

«Получатели»: свой личный чат и получатели из общего списка бота. Новые получатели добавляются через /recipient; для групп и каналов сохраняется проверка прав публикации. Удаление получателя из общего списка отсоединяет его и от этих источников. Добавление администратора не подписывает его автоматически на все источники.

«Последний пост» — явный запрос последней доступной публикации только запросившему администратору, независимо от слов и даты. Обычно обрабатывается в течение нескольких секунд, если сборщик подключён и Telegram не потребовал паузу. Запрос ожидает до 10 минут, один на администратора. Авторизация перепроверяется перед ответом, история автоматической отправки не меняется.

## Поведение и ограничения

- До 20 источников; автоматическая проверка каждые 5 минут после завершения предыдущего цикла. При первом успешном подключении текущий последний ID становится стартовой точкой: архив автоматически не рассылается, включая период до первой проверки. Для просмотра последней записи служит отдельная кнопка.
- После старта пересылаются новые посты, в том числе накопленные за время остановки. До 50 постов на канал за цикл, затем продолжение со следующего ID. Фильтры и новые получатели не пересчитывают уже пройденный архив.
- Отправляются текст/подпись, название канала, дата и активная ссылка на оригинал. Файлы, изображения и видео не копируются; для публикации без текста выводится ссылка с пометкой о медиа. Альбом может дать несколько ссылок. Правки и удаления старых постов не отслеживаются.
- SQLite хранит курсор и подтверждённые части отправок каждому получателю. Ошибка доставки не продвигает курсор за неотправленный пост; после восстановления обработка продолжается. При тайм-ауте после фактической доставки Telegram не даёт транзакционного подтверждения вместе с SQLite, поэтому в таком редком случае повтор возможен.
- Недоступность канала/аккаунта и ошибки получателя показываются как ошибка проверки, а не как отсутствие постов. Если username начинает вести на другой channel ID, сборщик останавливает этот источник; необходимо проверить его и явно удалить/добавить заново.
- Пауза FloodWait сохраняется в SQLite и соблюдается после перезапуска. Лимиты Telegram динамические; не увеличивайте частоту и число источников ради обхода ограничений. Закрытые каналы и недоступные аккаунту публикации не читаются.
- Конфигурация, квоты и история общие для всех разрешённых администраторов. Получение публикаций работает отдельным процессом и не размножается при назначении новых администраторов. Уже начатая общая рассылка может завершиться после удаления источника/отзыва доступа; новые запросы не принимаются.

Для остановки: `systemctl stop newsbot-telegram`. Не передавайте другим людям файл сессии. В случае компрометации отзовите соответствующую сессию в настройках Telegram, затем выполните вход заново при остановленном сборщике.
