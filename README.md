# Криптообзор в Telegram

Ежедневная подборка до пяти новых заголовков для каждого получателя из Google News RSS за последние 48 часов. Рубрики по умолчанию: регулирование (`regulation`), криптобанки (`cryptobanks`), ЦФА (`cfa`), мероприятия (`events`). Приоритет — мероприятия и свежие публикации. Это подборка заголовков, а не проверенный AI-анализ.

## Быстрый запуск: старые настройки работают

В Settings → Secrets and variables → Actions задайте secrets:
- `TELEGRAM_BOT_TOKEN` — токен бота.
- `TELEGRAM_CHAT_ID` — ID личного чата, группы или `@username` канала.

Отправьте боту /start для личного чата; для группы добавьте бота, для канала дайте право публиковать сообщения. Затем Actions → Crypto news to Telegram → Run workflow (ветка main).
Расписание: 05:00 UTC / 08:00 МСК, возможны задержки GitHub.

## Несколько получателей

Добавьте secret `TELEGRAM_TARGETS` с JSON:
```json
[
  {"chat_id": "-1001111111111", "categories": ["regulation", "cfa"]},
  {"chat_id": "@your_channel", "categories": ["events"]}
]
```

Один `TELEGRAM_BOT_TOKEN` используется для всех получателей.
`TELEGRAM_TARGETS` имеет приоритет над targets из файла и над `TELEGRAM_CHAT_ID`; получатель с прежним ID автоматически не добавляется. Если categories не указаны, получатель получает все рубрики. Пустые и неизвестные рубрики, пустые списки получателей и повторяющиеся ID считаются ошибкой до обращения к сети.

## Свои рубрики

Скопируйте `news-config.example.json` в `news-config.json`, замените примеры. В Actions → Variables создайте `NEWS_CONFIG_PATH=news-config.json`.
Файл может содержать:
- `categories`: объект с произвольными именами рубрик; каждая содержит непустые списки `queries` (поисковые запросы) и `keywords` (подстроки заголовка без учёта регистра).
- `targets`: список получателей с `chat_id` и необязательным `categories`.

Настроенные categories заменяют рубрики по умолчанию. Если categories отсутствуют, используются стандартные. Публикация относится к рубрике, если найдена её запросом и содержит хотя бы одно её ключевое слово; она может относиться к нескольким рубрикам. Фильтр рубрик и история применяются до лимита пяти новостей.

ID получателей можно хранить только в secret `TELEGRAM_TARGETS`, оставив в публичном файле лишь рубрики. Токен никогда не записывайте в файл.

## История и сбои

Локально история SQLite находится в `data/sent.sqlite3`; путь меняется через `NEWS_STATE_PATH`. Сохраняйте файл между запусками и запускайте только один экземпляр бота на эту историю.
Дедупликация ведётся отдельно для каждого chat_id по URL (без фрагмента) и нормализованному заголовку. Разные статьи на одну тему с разными URL и заголовками могут пройти как отдельные новости.

GitHub Actions автоматически создаёт ветку `bot-state` и сохраняет в ней `sent.sqlite3` после каждой рассылки, включая частичный сбой. Workflow требует разрешения Contents: write и возможности обновлять эту ветку. Не удаляйте ветку, если хотите сохранить историю. В публичном репозитории история (ID чатов и хеши новостей) публична; токен в ней не хранится.

Успешные сообщения отмечаются сразу; сбой одного получателя не мешает остальным. Следующий запуск повторяет только недоставленные новости, пока они входят в 48-часовое окно. Длинные подборки разбиваются на сообщения. Если подходящих новых новостей нет, сообщение не отправляется; при полностью пустом сборе сохраняется прежнее уведомление об отсутствии публикаций.

Если Telegram принял сообщение, но соединение оборвалось до подтверждения, либо запуск аварийно завершился до сохранения ветки, повтор возможен: Telegram sendMessage не предоставляет ключ идемпотентности. Ошибка сохранения истории отображается как сбой Actions и требует исправления до следующей рассылки.

## Проверка локально

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s . -p 'test_*.py' -v
```

Для отправки задайте переменные окружения и выполните `python bot.py`. Тесты подменяют RSS и Telegram: реальных сообщений не отправляют.
